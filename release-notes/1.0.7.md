# TX-5DR v1.0.7

## Changes

- Introduce a dedicated JTTY Workbench V1 for desktop and mobile, with independent receive, transmit, macro, and QSO panels (P0–P3).
- Preserve the existing JTTY native MFSK decoder/encoder, `transmitMfsk` physical-transmit confirmation, and `confirmMfskQso` QSO persistence path.
- Add revision-deduplicated JTTY receive transcript, AF selection, callsign selection, receive copy/follow controls, and F1–F12 editable message macros stored per browser/operator.
- Integrate JTTY-only recent QSO filtering, one-shot QSO confirmation, native manual logging, and en/zh/ja localization.
- Prevent stale transmission polling from overriding a STOP state and reject report shorthand (`5NN`, `599`, `R599`) in callsign recognition.
- Add dedicated JTTY front-end tests, submission tests, build-time locale verification, and code quality coverage.

## Validation

- Focused Radio Regression Tests: frontend/backend build, tests, Caddy/FRP checks, locale parity passed on the final implementation PR.
- FTDX10 CAT Protocol Regression, native six-mode smoke, addon isolation, full dynamic radio validation, Linux Server build, and aislop quality checks passed on the final implementation PR.
- v1.0.7 release packaging and publication are tracked separately in the official platform-release workflows.

## Scope and known limitations

- No real-radio RF or PTT hardware acceptance is claimed by these CI checks.
- JTTY macros are server-persisted per callsign and shared by authorized clients of the same station. Existing V1 local presets are imported when no server panel exists; custom shortcut bindings remain local.
- New native JTTY QSOs persist QTH and remarks through `confirmMfskQso` to the logbook's QTH and ADIF COMMENT fields.
- macOS signed/notarized releases are not part of this official Windows/Linux release workflow.
