# TX-5DR v1.0.4

## FTDX10 CAT control extensions

- P1: RX operating-mode arbitration and live mode/passband readback.
- P2: RF Gain, AGC, IPO, ATT, IF Shift, CW pitch, key speed, APF, and independent Roofing Filter / Contour controls.
- P3: Serialize all CAT commands through the existing Hamlib rig owner; reject malformed, unrelated, duplicate or incomplete EX/CO/RF responses.
- P4: Lift the global TX audio routing ban. Use the live SSB/AM/FM/DATA EX menu bank for MIC/USB/rear selection and readback.
- P5: Independently read/write Split TX mode on its own VFO without rewriting RX mode or TX frequency.
- P6: Typed regression, native fork CI, multilingual UI, static analysis and product packaging verification.

## Software acceptance / limitations

No physical FTDX10 was used during this release, as explicitly requested by the operator. Real-device validation is deferred to the operator.

The Yaesu CAT protocol does not include a per-request nonce: byte-identical late replies from the same register cannot be uniquely attributed. Wrong-register and malformed replies are checked in the application; this limitation does not justify a blanket feature ban.

The modified Hamlib fork passed isolated Linux native source/addon CI, but the distributed `hamlib@0.7.7` binary is **not represented as containing those fork-only changes**. Application-level validation and serialized ownership are independent. Native load tests for each package should be assessed from actual artifacts, not inferred from source-only success.
