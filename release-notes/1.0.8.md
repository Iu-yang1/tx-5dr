# TX-5DR v1.0.8

## Changes

- Upgrade the pinned native `mfsk-core-tx5dr` backend to upstream `mfsk-core v0.16.1` plus the fork-specific compatibility work, fixed at commit `4d1d15835bd35327e20aad3ea4eee3dd98cb2997` (TX-5DR PR #78).
- Bring in upstream WSPR/`wsprd` behavior parity, JT9/FT4 handling, waveform generation and native API improvements.
- Preserve fork-specific MSK40 shorthand frames, adaptive MSK144 equalization, and callsign hashing behavior.
- Improve native UTC progress and Auto TX recovery when toggling MFSK modes, slot timings and transmit submodes; cover operator progress and digital preference UI with regression tests.
- Align native module ABI/runtime probes and CI provenance with the merged DSP fork.

## Validation evidence

- The merged source commit `12ab45429e58ed71f422d7eeec413eaf6d53df9f` passed five native target build/test jobs, six-mode reference and DSP regressions, P0 native module isolation, full dynamic radio regression, targeted frontend/backend checks and aislop.
- The source commit's Windows x64, Linux x64/ARM64 desktop packaging, Linux Server amd64/arm64 packaging and Android Runtime ARM64 builds succeeded.
- Formal `v1.0.8` packaging, publication and distribution checks are separate from the above source-stage validation and must be verified from their own official workflow runs.

## Scope and limitations

- Official desktop distribution covers Windows and Linux. macOS signed/notarized distribution is not included in the configured official Windows/Linux workflow.
- The Host release includes Windows/Linux desktop, Linux Server and Docker. Android Runtime publication is a separate workflow; Android APK, Plugin SDK/npm and website releases are not part of this Host iteration.
- No physical-radio RF, PTT hardware or sensitivity-gain validation is claimed. Offline decoder regressions do not demonstrate a measured RF sensitivity improvement.
