# TX5DR v1.0.3

## Release scope

This release consolidates the following independently reviewed changes:

- Voice PTT safety: retain the logical lock until the physical TX lease is safely released; handle 180-second lock timeout, browser media loss, peer disconnect and unknown hardware stop recovery.
- Fake It: keep the logical RX dial stable while the CAT-controlled TX dial is temporarily shifted, discard asynchronous stale frequency observations and require RX dial restoration before another TX lease.
- Native Q65/WSPR/MSK144/JTTY receiver: server-owned, revisioned configuration replaces competing browser-local background starts. Only an explicit authorized save can reconfigure active RX; TX-only setting changes do not reset multi-period Q65 averaging.
- Q65 AP context: protect target hypotheses against competing browser sessions.
- Digital mode settings: viewing a different mode's configuration no longer switches the physical radio mode.
- Decoded-message double-click: localized acknowledgement identifies the target operator while distinguishing a sent request from remote acceptance.
- CI: upgrade to Yarn 4.12 to support the Git version used by GitHub-hosted runners.

No UI is added for AP/OSD execution timing, candidate truncation or actual decode-depth telemetry.

## Acceptance

The integration test source is PR #57 (combined from PR #48, #52, #54 and #56). Required gates are focused and full backend regression, web tests, native codec smoke, fork isolation, static native preference acceptance, Docker/Linux/Windows packaging and aislop quality review.

These checks test software and virtual/CI radio behaviour. **They do not substitute for physical CAT and RF testing.** Before relying on unattended remote voice PTT, verify the actual transceiver independently returns to receive after stop, timeout, network loss, and CAT errors; retain the radio's hardware TX timeout.

## Configuration and deployment

Native receiver preferences are now stored in server configuration. Browser-local preferences used by older versions are not automatically applied to a shared receiver. Review and explicitly save the Q65/WSPR/MSK144/JTTY configuration in one authorized browser after upgrading, especially Q65 submode/averaging and MSK144 call search.

Windows/Linux desktop, Linux server and Docker builds are produced by the versioned release dispatch on `main`. Do not publish a stable release until the combined validation is green.

## Rollback

Back up the server configuration before upgrading. Reinstall v1.0.2 if needed, stop all transmit activity first and verify the physical PTT is inactive. Older clients may resume browser-local native RX settings after rollback; they are not guaranteed to honor server-owned settings. Preserve backups for subsequent migration.
